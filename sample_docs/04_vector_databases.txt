A vector database stores embeddings and quickly finds the ones most similar to a query vector. Instead of scanning every vector, it uses approximate nearest neighbour indexes such as HNSW to search fast, even with millions of items. ChromaDB is a popular open-source vector database that is easy to run locally and stores the original text and metadata alongside each embedding. FAISS, created by Meta, is a library for efficient similarity search that works well when you need raw speed and control. A typical workflow is to split documents into chunks, embed each chunk, store the vectors, then embed the user question and ask the database for the top three or top five nearest chunks. Chunks are used because a whole document is too long to embed well and too long to place in a prompt, and smaller chunks make retrieval more precise.
